# PatchMon Home Assistant v0.2.2

## Entity IDs

- All newly created watched package update entities get `update.patchmon_*` IDs.
- Existing package update entities are renamed in Home Assistant's entity registry on reload, without changing their unique IDs or deleting entity data. This is intentionally a **breaking entity_id rename**: check automations, cards and custom JS resources referencing old IDs.
- If an ID is already occupied, the existing ID remains unchanged and a warning is logged; unrelated integrations are never renamed.

## Native update progress

- `update_percentage` and `in_progress` now reflect stage-based progress on watched package update entities (Home Assistant `UpdateEntityFeature.PROGRESS`).
- Milestones: queued **10%**, running/updating **55%**, agent-inventory verification **90%**. Waiting for approval or a delayed schedule is shown as an early-stage milestone.
- `patch_stage` exposes `queued`, `updating`, `verifying`, `completed`, `errored`, or `awaiting_inventory` on the update entity. `progress_type` is always `stage_based`.
- **Important:** PatchMon does not expose actual installation percentage. These milestones indicate state transitions, not bytes/packages installed. Terminal success is shown only after the fresh package inventory confirms the target package is up-to-date. If confirmation times out, `awaiting_inventory` is shown and normal polling can later mark the run `completed`.
- Real PatchMon run errors remain available in the existing *Last patch run* diagnostic sensor, including console tail.
- Authentication is unchanged: the username/password -> JWT path is retained until upstream PatchMon PR #596 lands.

## Testing

```bash
python3 -m compileall -q custom_components/patchmon
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

After updating and restarting Home Assistant, watch one noncritical host's update entity throughout a patch run, and verify the new `update.patchmon_*` entity IDs against existing UI resources.
