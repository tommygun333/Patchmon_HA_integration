# PatchMon Home Assistant v0.2.1

Apply the patch to a local checkout that contains v0.2.0. This patch does not
change the working username/password -> JWT authentication, and keeps the
`PatchMonClient._patch_request` boundary for upstream PR #596 bearer tokens.

## Fixes

- Local `translations/en.json` supplies the missing menu and option labels.
- After a package-specific HA Install action queues a run, HA follows its
  `patch_run_id` (about every 10 seconds, for up to 20 minutes) and then refreshes
  **only that host's** package inventory until the new report is available
  (another ~6 minutes max). This covers the gap between PatchMon marking the job
  complete and the updated agent inventory becoming visible.
- Host `Last patch run` diagnostic sensor displays the run status, timestamps,
  result/error, and the last 25 console lines (max 2048 characters). Full logs
  remain accessible in PatchMon. Runs launched through a native package update
  appear even if general background run monitoring is disabled. To monitor patch
  runs started outside Home Assistant, enable the existing optional setting.
- Unwatched package entities are automatically removed from HA's entity registry
  after an options reload; unrelated entities and watchlist entries on other
  hosts are untouched. The system does **not** delete unknown/missing packages
  which are still explicitly selected for tracking.
- Add GitHub workflows for HACS validation and Home Assistant hassfest validation,
  in addition to existing Python tests. These do not connect to PatchMon or HA.

## Test locally

```sh
python3 -m compileall -q custom_components/patchmon
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

After installing in Home Assistant, restart HA (translation files are cached).
If labels remain blank in a mobile app, reload its frontend or clear its cache.

**Important:** GitHub Actions HACS/hassfest validation runs after pushing; these
checks have not yet been observed against the proposed v0.2.1 commit. Test the
Install action on a noncritical host before deploying to production. Scheduled
runs that start more than 20 minutes after submission require the optional
regular patch-run monitoring and will reflect the eventual update on the next
package polling interval.
